## Objective
Transfer production snapshot publishing to Processing with one active publisher, compatible Redis contract, and recovery from an empty cache. **Do NOT remove dashboard calculation code from back-end yet** — only disable the publish flag. Legacy code stays runnable for rollback until Phase 9.

## Scope and implementation details
Follow [Phase 5 specification](https://github.com/svitlo-power/svitlo-power/blob/main/docs/architecture/phase-4-5-spec.md) and [migration thresholds](https://github.com/svitlo-power/svitlo-power/blob/main/docs/architecture/migration-thresholds.md). Keep this phase independently deployable and backward-compatible with adjacent phases.

## Exit criteria
All back-ends consume Processing snapshots; freshness/parity pass; rollback has been rehearsed. Legacy publish code disabled (flag off, no writes). **Legacy calculation code REMAINS** (removed in Phase 9).

## Rollback
Stop Processing publishing (`PROCESSOR_PUBLISH_ENABLED=false`, processor releases lease), verify inactive, then re-enable legacy publisher (`BACKEND_PUBLISH_ENABLED=true`, legacy acquires lease). Never allow competing writers.

## Dependencies / coordination
Track sequencing and parallel work in parent issue #181. Phase 7 is a parallel track. Do not cut over a producer or scheduled side effect while the previous owner is active.
